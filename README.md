# SmartVisit V3 — 통화 후 화면 위 팝업 + 한 번 눌러 MMS 직접 전송 시도 (검증 전 소스)

## 정확한 동작 목표
- 애니존 또는 기본 전화 앱에서 평소처럼 발신 통화 (SmartVisit에서 전화 걸지 않음)
- 통화 종료 시 *휴대폰 잠금 해제 상태에서* 화면 위에 `보내기 / 보내지 않기` 팝업 자동 표시
- `보내기` 한 번 누르면 삼성 메시지 앱을 열지 않고 이미지+문자 MMS 직접 전송 요청
- 앱 ON/OFF, 소속과 이름 이미지 자동 삽입, 중복 전송 경고와 이력 유지
- 갤럭시 기본 전화 앱과 기본 문자 앱은 교체하지 않는 방향

## 구현 변화 (V2.1 비교)
- 사용자가 ON으로 설정하면 포그라운드 통화 감지 서비스를 기동하고 지속 알림 표시
- `다른 앱 위에 표시` 특별 권한을 허용하면, 감지된 통화 종료 시 TYPE_APPLICATION_OVERLAY 팝업 시도
- 화면이 잠겨 있을 때는 전화번호 노출 위험 때문에 팝업 대신 알림 이용
- `SEND_SMS` 별도 권한 요청. 삼성 메시지 공유 화면을 거치지 않고 SmsManager.sendMultimediaMessage로 직접 전송 시도
- MMS PDU 인코딩은 Maven Central의 `com.klinkerapps:android-smsmms:5.2.6` 라이브러리 PduComposer 활용 (2020년 버전, 2026년 저장소 아카이브됨)
- MMS 결과 PendingIntent 방송을 통해 전송 성공 응답과 실패 코드 기록. 고객 수신 확인과는 구분.

## 현재 상태와 중요 제약
**V3 소스는 이 환경에서 Android SDK가 없어서 APK 컴파일을 실행하지 못했고 갤럭시/U+ 실제 MMS 발송 또한 시험하지 못했습니다.** Java/Manifest의 부분 정적 검사만 가능하며 정상 작동을 보증하지 않습니다.

- Android 14+ 화면 위 표시 및 포그라운드 서비스 규칙을 준수하도록 설계했으나 실제 삼성 기기/OS에서 차이가 있을 수 있습니다.
- 사용자 동의·실제 송신권한·업무 지침 확인 필수. `SEND_SMS`는 Google Play 배포 정책에서 기본 문자 앱 또는 예외로 제한합니다. 사내 테스트 APK 방식이라고 OS/통신사 발송이 반드시 허용되는 것은 아닙니다.
- 발신번호 식별에 CallScreeningService 역할이 필요하고, 수신자에게 전화 연결되었는지와 무관하게 통화종료 알림이 나타날 수 있습니다.
- 안드로이드 절전, 시스템 프로세스 재시작 등으로 서비스가 중단될 수 있습니다. ON 설정 저장만으로 재부팅 후 자동 기동된다고 가정하지 마세요. 앱을 다시 열어 ON 저장이 필요할 수 있습니다.
- 이 프로젝트는 실사용 고객번호로 테스트하기 전, **본인 소유 테스트 번호 1건**에서 팝업과 MMS 발송 결과를 반드시 확인해야 합니다.
- MMS는 별도 요금이 발생할 수 있으며 회사 정보·전화번호 사용 및 보안정책 승인이 필요합니다.

## 빌드
1. GitHub 저장소에 기존 `app`, `build.gradle`, `settings.gradle`, `.github` 폴더를 유지하면서 이 V3 프로젝트 파일을 올립니다. ZIP 파일을 한 개로 업로드하지 마세요.
2. GitHub Actions > `Build SmartVisit Debug APK` > 성공 실행에서 Artifacts 다운로드.
3. APK를 본인 기기에서 설치하고 *자기 번호*로 검증합니다.
4. 앱에서 소속/이름을 설정하고 통화 식별, 통화 상태, 알림, `다른 앱 위에 표시`, `MMS 전송` 권한을 승인한 후 ON을 저장합니다.
5. 테스트 시나리오: 자기 번호로 일반 전화 → 종료 → 즉시 팝업 → 보낼지 선택 → 휴대전화 메시지 앱이 열리지 않는지 → 문자 수신/결과 확인.

**핵심 주의:** 빌드 성공은 OS 권한·통신사 MMS 정상 발송 성공을 의미하지 않습니다. 전송 실패 시 팝업 문구, MMS 이력 및 기기 로그로 원인을 판별해야 합니다.
